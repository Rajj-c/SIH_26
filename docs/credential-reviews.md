# Institution credential reviews

Apply migration `202609220013_credential_reviews.sql` after 012. Students and institutions have a Credential Reviews navigation item; students also have a link from Portfolio. This is institution review, not independent issuer authentication or accreditation. Gemini does not decide authenticity.

A student chooses their own certification and an approved institution. Issuer text and either an evidence URL or attached document are required. Expired certificates cannot be submitted. Membership is checked and locked during the request and decision. An unchanged Pending or Approved request is reused. A changed version supersedes any pending request to the same institution and appends a history event.

Each request snapshots the portfolio record. A security-invoker view compares it to the current record. Editing/deleting a certificate makes its earlier review historical; expiry is displayed separately. Institutions can approve, request corrections or decline a current pending snapshot, with reasons; existing approvals can be revoked. Approval does not set `verified_at`, create assessment evidence, or lock student editing. The original snapshot, decisions, reasons and timestamps remain immutable to clients.

Only the student and the designated institution with a currently approved membership can read the request/history. Recruiters, other institutions and academicians receive no access from this feature. Revoking membership removes institution visibility and decision access; students retain history. This phase does not expose the institution-review status to recruiters or replace existing verification labels elsewhere. Private attachments continue using existing storage permissions and short-lived signed URLs; an old snapshot is not an immutable archive of the underlying file. Student deletion retains the snapshot/history, not the document itself. Account deletion and review-history retention policies need administrative design before production use.

Corrections: edit the certificate in Portfolio, then request a new review. Reviewed evidence URLs open externally; reviewers should only visit trusted links. Migration 014 adds private in-app notifications and direct review links; see `credential-review-notifications.md`. No external issuer API, email reminder, public verification page, QR credential, or AI certification is added. The page refreshes periodically. Review requests and decisions are saved in Supabase without mock data.

Automated disposable-database checks cover ownership, membership, unrelated-account isolation, immutable events, idempotent requests, stale-version approval rejection, superseding, corrections, revocation, membership loss, deletion history and absence of skill verification. Live multi-account and browser checks remain after migration activation.
